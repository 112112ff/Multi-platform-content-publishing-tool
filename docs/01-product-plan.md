# 产品与功能规划

## 页面结构

MVP 采用工作台式页面，不做空洞营销首页。评委打开项目后应立即看到可操作界面。

推荐布局：

```txt
顶部导航：产品名、当前草稿状态、主要操作
左侧区域：原始内容输入
中间区域：平台适配预览
右侧区域：发布体检、一键发布、发布结果
底部区域：真实投递结果记录
```

## 核心模块

### 1. 原始内容输入

字段：

- 标题
- 正文
- 标签
- 封面图 URL
- 视频链接
- 目标平台选择

交互要求：

- 支持一键载入示例内容。
- 输入内容变化后可以重新适配。
- 标签可以用逗号或回车拆分。

### 2. 平台适配

目标平台：

- 公众号
- 知乎
- B站
- 小红书
- 微博
- 抖音

每个平台生成内容：

- 平台标题
- 平台正文
- 标签或话题
- 摘要或简介
- 适配说明
- 平台策略信息

### 3. 平台策略卡片

每个平台展示低成本但高价值的信息：

- 平台定位
- 内容策略
- 推荐语气
- 发布风险
- 适配理由

示例：

```txt
小红书
平台定位：生活方式与种草内容
内容策略：短句、强场景、话题标签
适配理由：已将长段落拆成短句，并补充话题标签，适合移动端快速阅读。
```

### 4. 发布健康分

每个平台根据校验规则生成 0 到 100 分。

分数示例：

```txt
公众号 92：结构完整，建议补充封面图。
知乎 88：观点明确，建议增加讨论式结尾。
B站 65：缺少视频链接，无法正式发布。
小红书 90：标签充足，标题可以更短。
```

### 5. 预览编辑

用户可以对每个平台生成后的标题、正文和标签进行微调。

MVP 可以先做：

- 文本框编辑平台标题。
- 文本框编辑平台正文。
- 标签文本编辑。

### 6. 真实投递

点击真实投递后，系统根据发布体检结果决定是否向接收端发送 HTTP POST。

发布状态：

- 成功
- 失败
- 草稿

发布结果字段：

- 平台
- 状态
- 发布时间
- 模拟链接
- 失败原因
- 健康分

### 7. 投递结果

记录每次真实投递结果。

MVP 可以使用浏览器本地状态保存，不强制接数据库。

## 功能优先级

### P0 必须完成

- 内容输入表单
- 示例内容按钮
- 六个平台适配结果
- 适配说明
- 发布健康分
- 发布校验
- 真实 Webhook 投递
- README 和架构说明

### P1 应该完成

- 平台预览编辑
- 真实投递结果记录
- 更好的空状态、错误状态和加载状态
- Demo 友好的示例数据

### P2 有余力再做

- 导出 Markdown
- 多草稿管理
- 平台模板自定义
- 接入真实大模型 API 的配置入口
- 定时投递任务

## Demo 推荐流程

1. 打开项目，介绍 ContentBridge 的目标。
2. 点击“载入示例内容”。
3. 点击“一键适配”。
4. 展示六个平台生成内容的差异。
5. 展示适配理由和健康分。
6. 修改小红书或 B站版本。
7. 点击“一键发布”。
8. 展示成功、失败和草稿结果。
9. 打开 README 或架构文档，讲新增平台方式。

## 产品表达重点

Demo 中要反复强调：

- 不是复制粘贴，而是平台风格适配。
- 不是只生成内容，而是发布前会体检。
- 不是真实平台 API 炫技，而是稳定可扩展的发布编排 MVP。
