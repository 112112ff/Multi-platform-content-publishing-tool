# 项目总览

## 项目名称

ContentBridge 内容桥

## 参赛议题

题目二：多平台内容发布工具

## 一句话介绍

ContentBridge 是一个面向创作者的多平台内容发布助手，支持一次输入内容，自动适配公众号、知乎、B站、小红书、微博、抖音等平台格式与风格，并通过发布体检和真实 Webhook 投递帮助用户更高效地完成多平台分发。

## 用户问题

很多创作者会把同一份内容发布到多个平台，但不同平台的内容形态差异很大：

- 公众号更适合结构清晰、完整表达的长图文。
- 知乎更看重观点、论证和问答语境。
- B站需要视频简介、分区、标签和互动引导。
- 小红书偏短句、生活化表达、话题标签和种草语气。
- 微博适合短观点、热点话题和评论互动。
- 抖音需要前三秒钩子、口播脚本和镜头提示。

手动改写会消耗大量时间，复制粘贴又容易造成风格不适配、标题过长、缺少封面、缺少视频链接等问题。

## 产品定位

ContentBridge 不是单纯的同步发布按钮，而是一个“平台内容适配专家”：

1. 帮用户把一份原始内容改写成不同平台版本。
2. 告诉用户每个平台为什么这样适配。
3. 在发布前做健康检查，减少发布失败和效果不佳的风险。
4. 用统一的适配器架构支持后续扩展更多平台。

## MVP 范围

本期 72 小时内重点完成以下闭环：

```txt
输入内容 -> 选择平台 -> 自动适配 -> 预览编辑 -> 发布体检 -> 真实投递 -> 投递结果
```

## 明确不做

为了确保 72 小时内完成可演示 MVP，本期暂不做以下能力：

- 不接入真实公众号、知乎、B站、小红书发布 API。
- 不做复杂账号体系和 OAuth 授权。
- 不做多人在线协同编辑。
- 不依赖真实大模型能力完成核心流程。

如时间允许，可补充“未来可接入大模型”的设计说明，但核心 Demo 必须使用稳定可控的规则引擎完成。

## 作品亮点

- 平台风格差异明显，不是简单复制内容。
- 每个平台都有适配理由，体现产品智能感。
- 发布健康分和校验提示让工具更实用。
- 真实 Webhook 投递和结果反馈形成完整产品闭环。
- `PlatformAdapter` 架构清晰，便于扩展更多平台。

## 成功标准

作品完成后，应能在 Demo 中清晰展示：

- 用户输入一份原始内容。
- 系统生成四个平台的不同版本。
- 用户看到每个平台的适配说明、健康分和校验问题。
- 用户修改某个平台版本后真实投递到接收端。
- 系统展示发布结果和历史记录。
- README 说明如何新增第五个平台。
