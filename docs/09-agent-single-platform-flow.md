# Agent 单平台发布流程说明

本轮产品调整把主流程从“六平台工作台”改成“Agent 引导的单平台发布”。目标是让普通创作者不用理解 Webhook、账号矩阵、平台适配器等专业概念，也能按自然语言完成一次发布准备。

## 用户主流程

```txt
用户输入一句话
  -> Agent 判断最适合的单个平台
  -> 生成该平台草稿
  -> 弹出该平台账号确认
  -> 用户确认已在浏览器登录
  -> 一键发送到平台草稿 / 浏览器扩展
  -> 用户在官方页面最终确认发布
```

## 为什么只弹一个平台账号

旧版本在用户输入后会展示多个平台账号，容易让用户误以为必须完成复杂配置。现在 Agent 会根据用户话术优先选择一个平台：

- 提到“小红书、笔记、种草”时优先小红书。
- 提到“知乎、问答、专业分析”时优先知乎。
- 提到“B站、教程、视频教程”时优先 B站。
- 提到“公众号、微信、长文、私域”时优先公众号。
- 提到“微博、热搜、话题”时优先微博。
- 提到“抖音、短视频、口播”时优先抖音。

如果用户没有明确平台，默认先走小红书，因为图文草稿最容易演示完整闭环。

## 一键发布的真实边界

当前项目不伪造“已经发到官方平台”的结果。真实可跑通链路分两类：

1. 浏览器扩展发布桥：复用用户自己的浏览器登录态，打开单个平台创作页并填充草稿，最终由用户人工点击发布。
2. 测试接收端：把草稿真实 POST 到用户提供的接收服务，用来证明发布 payload、状态处理和失败反馈能跑通。

主界面默认把“浏览器扩展发布桥”作为普通用户的一键发布入口；“测试接收端”收进开发验证入口，避免干扰普通用户。

## 和 MultiPost 类项目的关系

MultiPost 的核心启发是浏览器扩展路线：用户不把账号密码交给第三方系统，而是使用本机浏览器登录态完成平台创作页辅助填充。ContentBridge 没有复制 MultiPost 代码，而是在本项目中实现了自己的 `extension/` 发布桥，并把它接入 Agent 主流程。

## 后续扩展

- 增加“多平台批量模式”，但默认仍保持单平台引导。
- 接入真实后端 Publisher，用 OAuth 或平台开放 API 替换测试接收端。
- 为每个平台维护更稳定的 DOM 填充策略。
- 增加发布前素材检查，例如封面图、视频文件、话题标签和发布时间。
