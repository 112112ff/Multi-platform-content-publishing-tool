# 提交规则与验收清单

## 比赛时间

```txt
开始：2026-05-29 00:00
截止：2026-05-31 23:59
周期：72 小时
```

所有 commit 时间戳必须落在上述时间范围内。

## 必交内容

- 公开可访问的 GitHub / Gitee 仓库。
- Demo 视频。
- README 文档。

开发过程可以先保持仓库 Private，提交截止后必须改为 Public，确保评委可访问。

如果项目后续拆出多个独立模块，必须放在同一个仓库的不同子目录中，例如：

```txt
frontend/
backend/
docs/
```

本项目当前优先采用单一前端工作台实现，降低部署和演示成本。

## 作品有效性要求

必须满足：

- 作品方向符合题目二：多平台内容发布工具。
- 仓库在开题后创建。
- 开发周期内持续提交。
- 两名队员都使用各自账号提交 commit。
- PR 描述完整且与实际变更一致。
- README 列明第三方依赖。
- README 说明原创功能部分。
- 如复用过去代码，必须在 PR 描述中注明来源。
- 不提交任何未经许可的第三方代码或素材。
- 如使用图片、图标、字体、开源库等外部资源，必须在 README 中说明来源和用途。

无效风险：

- 最后一天一次性导入所有代码。
- commit 时间不在比赛周期内。
- PR 描述空白。
- PR 描述与实际代码严重不符。
- 依赖没有在 README 说明。
- 复用过去代码但未注明来源。
- 仓库最终仍为 Private，评委无法访问。
- Demo 视频链接不可播放或需要特殊权限。

## 知识产权与学术诚信

项目代码和文档应由队伍自主完成。严禁抄袭他人项目或大段复制公开代码。

如果确实参考了公开资料、开源库、模板或历史代码，必须做到：

- 在 PR 描述中说明来源。
- 在 README 的依赖或参考资料中说明。
- 明确区分第三方依赖和本项目原创功能。

默认参与活动即同意主办方按规则公开作品源代码，并可免费使用投递作品进行演示和出版展示。本项目不得包含敏感信息、账号密码、密钥或未经授权的单位内部资料。

## PR 规则

每个 PR 只做一件事。

PR 描述必须包含：

1. 标题：一句话说明本 PR 新增或修改了什么。
2. 功能描述：说明功能作用和使用方式。
3. 实现思路：说明技术选型或核心实现逻辑。
4. 测试方式：说明如何验证功能正常运行。
5. 分工说明：说明由谁完成，便于体现两人协作。

每个 PR 合并后，`main` 分支必须保持可运行。

## Demo 视频要求

视频必须用声音完整讲解，并覆盖核心模块。

推荐时长：4 到 6 分钟。

推荐结构：

1. 介绍题目和产品定位。
2. 展示输入或载入示例内容。
3. 展示公众号、知乎、B站、小红书、微博、抖音 6 个平台适配结果。
4. 展示平台适配理由、健康分和发布前校验问题。
5. 修改一个平台版本，并展示恢复生成版本。
6. 展示发布编排面板中的就绪、待补素材、阻塞和发布中状态。
7. 使用 Webhook 实发模式，把内容真实 POST 到外部接收端。
8. 展示 Webhook 接收端收到的 JSON payload。
9. 展示发布结果和历史记录。
10. 新增一个自定义平台，证明扩展更多平台是可运行功能。
11. 讲解 `PlatformAdapter` 与 `createCustomPlatformAdapter` 扩展架构。
12. 说明两人分工和持续 PR 过程。

详细录制脚本见 [06-demo-script.md](./06-demo-script.md)。

- 仓库已改为 Public。
- README 中 Demo 视频链接可打开。
- README 中依赖说明完整。
- README 中原创功能说明完整。
- PR 描述没有空白。
- commit 时间均在 2026-05-29 至 2026-05-31。
- 两名队员都有 commit。
- `main` 分支可以本地运行。
- 演示流程不依赖临时数据或未提交文件。
- 没有提交 `.env`、密钥、账号密码等敏感信息。
- 未登录或隐身窗口下可以打开仓库。
- Demo 视频在外部平台可播放，README 中链接正确。
