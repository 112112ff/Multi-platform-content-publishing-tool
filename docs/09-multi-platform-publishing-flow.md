# 发布助理多平台发布流程说明

本项目的主流程是“用户提供原文或创作意图，发布助理整理需求，再生成六个平台的可编辑发布包”。它不再让用户先理解 Webhook、账号矩阵、适配器等专业概念，而是把复杂能力收进一个面向普通创作者的发布流程里。

## 用户主流程

```txt
输入原文或一句创作需求
  -> 发布助理追问主题、目标人群、风格、长度和热点素材
  -> 生成公众号、知乎、B站、小红书、微博、抖音六个平台草稿
  -> 用户在右侧预览页逐个平台微调标题、正文和标签
  -> 生成发布队列和发布体检
  -> 打开官方创作页 / 浏览器扩展填充 / Webhook 测试接收
  -> 用户最终确认发布
```

## 为什么默认生成六个平台

比赛题目关注的是“多平台同步发布”和“自动适配各平台格式与风格”。因此默认结果必须让用户一眼看到同一份内容在不同平台上的差异：

- 公众号：长文结构、导语、分段和总结。
- 知乎：问题意识、观点展开、讨论式结尾。
- B站：视频简介、章节提示、互动引导。
- 小红书：短句、场景化表达、种草标签。
- 微博：短观点、话题标签、转发讨论点。
- 抖音：口播脚本、前三秒钩子、评论引导。

用户仍然可以只选择一个平台发布，但生成阶段保持多平台视图，便于对比和批量分发。

## 账号与发布边界

国内内容平台通常没有稳定开放的一键发布 API，或者需要企业资质、OAuth、内容审核和平台侧权限。ContentBridge 不伪造“已发到官方平台”的结果，而是提供三条真实可跑通的链路：

1. 官方创作页路线：为每个平台生成可复制草稿，打开用户自己的官方创作后台，由用户确认发布。
2. 浏览器扩展路线：把草稿发送给本地扩展，扩展复用用户自己的浏览器登录态打开创作页并尝试填充。
3. 测试接收端路线：把草稿真实 POST 到用户提供的接收 URL，用于验证 payload、队列状态和失败反馈。

这个边界能保证演示真实可信，也符合 MVP 阶段的可交付范围。

## 和 MultiPost 类项目的关系

MultiPost 给本项目的启发是“浏览器扩展发布桥”路线：不收集用户平台账号密码，而是复用用户自己的浏览器登录态辅助填充官方创作页。ContentBridge 没有复制 MultiPost 代码，而是在本仓库中实现了自己的 `extension/` 发布桥和前端发布队列。

## 后续扩展

- 接入微博热搜、知乎热榜、B站热门、抖音热点榜等趋势源，统一输出给 `TrendSource`。
- 针对每个平台维护更稳定的 DOM 填充策略和失败回退提示。
- 在后端新增 Publisher 编排服务，支持官方 API、OAuth 授权和发布审计。
- 增加定时发布、素材库、封面检查、视频文件检查和团队协作审批。
