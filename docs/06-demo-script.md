# Demo 录制脚本

建议时长：4 到 6 分钟。

## 录制前准备

1. 安装依赖并启动项目：

```bash
npm install
npm run dev
```

2. 打开页面：

```txt
http://127.0.0.1:5173/
```

3. 准备一个真实接收端 URL。推荐使用 `https://webhook.site/` 创建临时 URL，也可以使用团队自建后端。
4. 如果要展示平台创作页辅助填充，按 [extension/README.md](../extension/README.md) 安装 ContentBridge Publisher Bridge 浏览器扩展，并提前登录目标平台账号。

## 讲解结构

### 1. 开场定位

建议话术：

> 我们选择的是题目二，多平台内容发布工具。ContentBridge 不是简单复制粘贴工具，而是一个面向创作者的 Agent 发布助手。用户先用一句话说明目标，系统再生成不同平台版本，并完成发布体检、账号矩阵任务、真实 Webhook 投递和浏览器扩展辅助填充。

要点：

- 对应题目二。
- 支持公众号、知乎、B站、小红书、微博、抖音。
- 当前真实投递链路包括 HTTP POST 到用户配置的接收端，以及浏览器扩展打开平台创作页辅助填充草稿，不伪造官方平台发布结果。

### 2. 爆品灵感库

操作：

1. 页面初始状态下展示右侧爆品灵感库。
2. 点击一个平台案例，展示内容拆解弹窗。

要点：

- 解决普通用户“不知道怎么写、为什么这样写”的问题。
- 展示不同平台内容形态差异。

### 3. Agent 对话生成内容

操作：

1. 在左侧 Agent 输入：

```txt
帮我写一篇 AI 学习效率的小红书和知乎文案，语气真实一点
```

2. 点击生成预览。
3. 展示右侧标题、正文和标签。

要点：

- 用户从一句话开始，不需要先填写复杂表单。
- Agent 会根据平台关键词选择目标平台并生成草稿。

### 4. 多平台适配与编辑

操作：

1. 切换小红书、知乎、B站、公众号等平台 tab。
2. 展示每个平台不同的标题、正文结构、标签和健康分。
3. 手动修改当前平台标题或正文。

要点：

- 小红书偏体验和种草。
- 知乎偏观点和论证。
- B站、抖音偏视频脚本和互动。
- 公众号偏长文结构。

### 5. 发布体检与账号矩阵

操作：

1. 展示右侧发布体检结果。
2. 展示 Agent 热点洞察。
3. 点击账号连接入口。
4. 展示公众号、知乎、B站、小红书、微博、抖音的登录/创作入口和连接状态。

要点：

- 账号确认不会提交真实账号、密码、Cookie 或 token，只用于记录用户已在浏览器完成平台登录。
- 真正接入官方平台时，需要 OAuth、平台开放接口或用户授权登录态。
- 矩阵运营引擎会把内容任务映射到账户、热点、素材和发布路线。

### 6. 真实 Webhook 投递

操作：

1. 从 webhook.site 复制临时接收 URL。
2. 回到项目，在“真实投递接收端”输入 URL。
3. 点击“真实投递到接收端”。
4. 切到 webhook.site，展示收到的 POST 请求和 JSON payload。
5. 回到项目，展示成功、失败或被体检拦截的结果。

要点：

- 这是实际 HTTP POST，不是按钮假状态。
- 如果没填 URL 或内容体检未通过，系统会阻断，不伪造成功。
- 未来可以把接收端替换为带 OAuth 的后端 Publisher。

### 7. 浏览器扩展 Publisher Bridge

操作：

1. 确认 Chrome / Edge 已加载 `extension` 目录下的扩展。
2. 在 ContentBridge 页面点击“发送到浏览器扩展”。
3. 展示扩展打开的平台创作页。
4. 如果页面 DOM 被识别，展示标题/正文自动填入；如果没有识别，展示右下角草稿面板并复制内容。

要点：

- 这是国内平台更现实的一键发布路线：利用用户自己的浏览器登录态，不要求用户把账号密码交给系统。
- 扩展不保存密码、Cookie 或 token。
- 最终发布仍由用户在官方页面确认，避免伪造发布成功。

### 8. 架构说明

建议展示文件：

- `src/types/platform.ts`
- `src/adapters/registry.ts`
- `src/services/adaptContent.ts`
- `src/integrations/matrixOperationEngine.ts`
- `src/services/extensionBridge.ts`
- `extension/background.js`

建议话术：

> 平台差异被封装在 PlatformAdapter 中，每个平台实现 adapt、validate、publish。矩阵运营引擎负责账号通道、热点任务和发布路线。真实平台接入有三条路线：Webhook 接收端、浏览器扩展 Bridge、官方 OAuth Publisher。前端主流程不需要重写。

### 9. 工程合规

要点：

- 仓库在开题后创建。
- 通过多个小 PR 持续提交。
- README 列明依赖和原创功能边界。
- Demo 视频链接最终补到 README。
- 截止后仓库改为 Public。
- 两名队员都要有各自账号的 commit / PR。

## 录制检查清单

- 声音清楚。
- 页面缩放合适。
- 展示 Agent 生成内容。
- 展示至少两个平台的不同改写。
- 展示发布体检。
- 展示账号连接弹窗。
- 展示 webhook.site 收到真实 POST。
- 如时间允许，展示浏览器扩展打开平台创作页并填充草稿。
- README 中补充 Demo 视频链接。
