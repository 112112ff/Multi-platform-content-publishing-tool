# 下一轮 Agent-first 重构计划

## 背景判断

当前版本已经具备多平台适配、发布体检、Webhook 投递、自定义平台和发布记录等能力，但从普通用户视角看仍然有几个明显问题：

- 首页信息过多，像专业运营工作台，不像普通创作者可以直接使用的助手。
- 手动输入项和配置项太多，用户容易不知道先做什么。
- Agent 已经出现，但还不是完整主流程，更像页面上的一个功能块。
- Webhook 对普通用户仍然偏技术化，不适合最终作为核心发布方式。
- 真实发布链路还不完整，目前没有账号登录、平台授权、平台发布状态同步。

下一轮目标是把产品从“多功能工作台”重构为“普通用户先对话，系统再逐步引导完成发布”的体验。

## 新产品定位

ContentBridge 应该是一个面向广大用户的多平台发布助手：

```txt
用户说一句话
  -> Agent 理解发布目标
  -> 系统改写为结构化发布需求
  -> 推荐平台和素材要求
  -> 用户确认或选择
  -> 系统生成各平台版本
  -> 用户在简洁弹窗里预览和微调
  -> 登录账号并授权平台
  -> 一键发布或保存草稿
```

普通用户默认不应该看到复杂工作台。复杂配置只在用户需要时出现。

## 首页重构目标

首页只保留三类内容：

1. **Agent 主输入区**
   - 一个大输入框：用户描述想发布什么。
   - 示例指令按钮：如“帮我发一篇小红书笔记”“把这段内容同步到公众号和知乎”“做一条抖音口播脚本”。
   - 主按钮：`开始生成发布方案`。

2. **项目指引 / 演示入口**
   - 3 到 4 个极简步骤说明：
     - 说出目标
     - 确认平台
     - 预览内容
     - 授权发布
   - 一个 `查看演示流程` 按钮。

3. **当前能力说明**
   - 支持的平台。
   - 当前真实能力：内容生成、平台适配、发布体检、外部接收端投递。
   - 计划能力：账号授权后一键发布。

首页不展示：

- 平台编辑器
- 自定义平台长表单
- 发布历史长列表
- Webhook 技术配置
- 大量健康分细节

这些内容应进入后续窗口或高级设置。

## Agent 主流程设计

### 第一步：理解需求

用户输入自然语言，例如：

```txt
我想把一篇关于 AI 学习效率的内容发到小红书和抖音，语气轻松一点，适合大学生。
```

Agent 输出结构化结果：

```txt
主题：AI 学习效率
目标人群：大学生
推荐平台：小红书、抖音
语气：轻松、直接、有行动感
素材需求：抖音需要视频素材
下一步：确认平台和内容方向
```

页面以弹窗或步骤面板展示，不要直接铺满全屏。

### 第二步：确认平台

弹窗展示推荐平台：

- 小红书：适合种草和经验分享
- 抖音：适合短视频脚本和口播
- 公众号：适合长文沉淀
- 知乎：适合观点讨论

用户可以勾选或取消。

### 第三步：生成内容

生成后只展示简洁卡片：

- 平台名称
- 标题
- 摘要
- 风险状态
- `预览 / 编辑` 按钮

点击后再打开该平台的细节窗口。不要把所有平台正文同时堆在首页。

### 第四步：发布前确认

统一确认弹窗：

- 已选平台
- 是否缺素材
- 是否需要登录
- 发布方式：
  - 保存草稿
  - 外部接收端测试
  - 已授权平台发布

### 第五步：发布结果

发布结果应以简短列表展示：

- 平台
- 状态
- 链接或失败原因
- 重新发布 / 查看详情

## 真实发布路线调整

当前 Webhook 只能证明系统可以真实把内容发送到外部服务，但对普通用户不是最终发布体验。

下一轮应把真实发布路线改为“账号登录 + 平台授权”：

```txt
用户登录 ContentBridge
  -> 绑定平台账号
  -> 获取平台授权 token
  -> 后端保存 token
  -> 前端发起发布请求
  -> 后端调用平台开放 API
  -> 返回发布状态
```

### 前端需要新增

- 登录入口：`登录 / 注册`
- 平台连接中心：
  - 公众号：未连接 / 已连接
  - 知乎：未连接 / 已连接
  - B站：未连接 / 已连接
  - 小红书：未连接 / 已连接
  - 微博：未连接 / 已连接
  - 抖音：未连接 / 已连接
- 发布按钮根据连接状态变化：
  - 未连接：`去连接账号`
  - 已连接：`发布到平台`
  - 不支持官方接口：`保存草稿 / 复制内容`

### 后端需要新增

建议下一轮新增 `/backend`：

```txt
backend/
  src/
    auth/
    platforms/
      wechat/
      zhihu/
      bilibili/
      xiaohongshu/
      weibo/
      douyin/
    publish/
    storage/
```

MVP 后端能力：

- 用户登录状态。
- 平台账号连接状态。
- 平台 token 的模拟保存。
- 发布接口抽象。
- 对没有官方接口或暂时无法接入的平台，返回清晰的“需要人工发布 / 仅支持草稿”状态。

### 平台接口现实约束

并非所有平台都能在 72 小时内完成真实官方发布：

- 有的平台开放接口需要企业资质或审核。
- 有的平台发布接口不对普通开发者开放。
- 有的平台需要 OAuth、签名、回调 URL、内容审核。
- 小红书、抖音等平台的正式发布接口可能存在权限门槛。

所以项目应诚实区分三种发布能力：

1. **官方 API 发布**：有授权、有接口、有状态回传。
2. **草稿 / 辅助发布**：系统生成内容，用户复制或跳转人工发布。
3. **外部接收端投递**：用于 Demo 和自动化集成验证。

不要把所有平台都假装成已官方直发。

## 页面结构建议

```txt
/
  Agent 首页
  - 主输入框
  - 示例需求
  - 演示入口

/flow
  发布流程弹窗/步骤面板
  - 需求理解
  - 平台确认
  - 内容生成
  - 发布确认
  - 发布结果

/connections
  平台连接中心
  - 账号登录
  - 平台授权状态
  - 连接/断开

/advanced
  高级工作台
  - 平台内容编辑
  - 自定义平台
  - Webhook 测试
  - 发布历史
```

如果不引入路由，也可以用页面内弹窗和阶段状态实现，但视觉上必须让首页保持干净。

## 下一轮功能优先级

### P0：必须先做

- 首页只保留 Agent、项目指引、演示入口。
- Agent 输入后打开步骤弹窗。
- 将高级工作台、自定义平台、发布历史移入高级区。
- 平台确认步骤。
- 平台内容卡片式预览。
- 发布前确认弹窗。

### P1：增强真实实用性

- 平台连接中心 UI。
- 用户登录 UI。
- 模拟账号连接状态。
- 发布按钮根据连接状态切换。
- 明确哪些平台支持真实官方发布、哪些只支持草稿。

### P2：可选加分

- 后端目录和 API skeleton。
- OAuth / token 存储接口模拟。
- 发布任务状态轮询。
- 演示模式数据重置按钮。
- 移动端优化。

## 下一轮 PR 拆分建议

1. `refactor: simplify homepage around agent entry`
   - 首页只留 Agent 和指引。
   - 原工作台移入高级区。

2. `feat: add guided publishing modal`
   - Agent 输入后进入步骤弹窗。
   - 需求理解、平台确认、生成内容、发布确认。

3. `feat: add platform connection center`
   - 登录入口。
   - 平台连接状态。
   - 模拟授权连接。

4. `feat: route publish through connection status`
   - 已连接平台走发布。
   - 未连接平台提示连接。
   - 不可直发平台保存草稿。

5. `docs: update demo script for consumer flow`
   - 更新 README 和 Demo 视频脚本。

## 给下一个 Codex 的执行提示

下一轮不要继续在当前首页堆组件。优先做信息架构重构：

- 首页干净。
- Agent 是唯一主入口。
- 复杂能力后置。
- 所有流程用步骤弹窗承接。
- 对“真实发布”诚实分级，不假装平台都已官方接入。
- 保留现有适配器和测试，减少重写风险。

建议先从 `src/App.tsx` 和 `src/styles.css` 重构布局，不急着新增后端。等前端流程顺了，再加 `/backend` skeleton。
