# 参赛提交说明

## 01 本期议题

作品开发时间：

```txt
2026-05-29 00:00 - 2026-05-31 23:59
```

本项目选择：

```txt
题目二：多平台内容发布工具
```

议题要求：

- 创作者在工具中输入内容。
- 系统自动适配公众号、知乎、B站、小红书等平台的格式与风格。
- 支持一键发布，可选模拟发布。
- 需要给出扩展更多平台的架构设计。

本项目对应实现：

- Agent 对话式入口：用户通过对话商讨内容方向，减少复杂表单操作。
- 多平台改写：支持公众号、知乎、B站、小红书、微博、抖音 6 个平台的差异化内容生成。
- 传达度评分与发布体检：从标题、结构、素材、互动引导、平台约束等维度给出发布前反馈。
- 账号矩阵与发布任务：为多个自媒体账号的登录、素材检查、发布确认和任务编排提供底层模型。
- 热点洞察：在用户生成前提供平台热点拆解和创作灵感，在 Agent 流程中辅助选题。
- Webhook 投递：用真实 HTTP POST 验证发布链路，后续可替换为官方 API 或授权发布服务。
- 可扩展架构：通过 `PlatformAdapter` 和矩阵运营引擎扩展更多平台。

## 03 作品提交规则对照

### 3.1 须提交内容

- 公开 GitHub 仓库：提交截止后将仓库设为 Public，确保评委可访问。
- Demo 视频：录制后补充到 README。
- README 文档：已包含项目定位、运行方式、依赖、原创功能、架构扩展和验收方式。

### 3.2 作品有效性

本项目按题目二开发，不提交上周议题方向。

合规要求：

- 开发周期内持续通过 PR 和 commit 推进。
- commit 时间应落在 2026-05-29 00:00 到 2026-05-31 23:59 之间。
- PR 描述不能空白，需要和实际变更一致。
- README 已列明第三方依赖和原创功能边界。
- 不提交密钥、账号密码、Cookie、`.env` 等敏感信息。
- 未经授权的第三方项目代码不进入仓库。

### 3.3 PR 提交规范

每个 PR 只做一件事。

PR 描述建议包含：

```md
## 功能描述
说明本 PR 新增或修改了什么，以及用户如何使用。

## 实现思路
说明核心设计、数据结构、组件或服务如何协作。

## 测试方式
列出本地运行、构建、单元测试或页面验证步骤。

## 分工说明
说明由哪位同学完成，便于评委判断协作过程。
```

主分支要求：

- PR 合并后 `main` 必须可运行。
- 任意时间评委拉取 `main` 后，应能通过 README 复现演示流程。
