# 参赛提交说明

## 议题对应

本项目选择题目二：多平台内容发布工具。

题目要求与当前实现对应如下：

- 用户输入内容：通过左侧 Agent 对话输入主题、受众、平台和语气。
- 自动适配平台格式与风格：通过 `PlatformAdapter` 生成公众号、知乎、B站、小红书、微博、抖音版本。
- 一键发布：当前不伪造官方平台直发，提供可跑通的 Webhook 真实投递链路和浏览器扩展 Publisher Bridge。
- 扩展更多平台：通过平台适配器和矩阵运营引擎扩展账号、授权、热点、任务和发布路线。

## 当前真实能力

- Agent 生成内容草稿。
- 多平台差异化改写。
- 发布体检与风险提示。
- 账号矩阵任务规划。
- 热点洞察与改写建议。
- 填写接收端 URL 后，对所选平台任务执行真实 HTTP POST。
- 加载浏览器扩展后，把发布任务发送给扩展，打开平台创作页并尝试填充草稿。

## 演示能力边界

当前版本不会假装已经接入各平台官方发布接口。

真实官方直发通常需要：

- 平台开放 API。
- OAuth 或平台登录态。
- 内容审核与发布权限。
- 服务端保存 token 或安全 Cookie。

因此当前 MVP 的真实链路是：

```txt
Agent 生成内容
  -> PlatformAdapter 平台化改写
  -> 发布体检
  -> MatrixOperationEngine 生成账号任务
  -> Webhook / 自建后端真实接收 POST payload
  -> 或浏览器扩展打开平台创作页并辅助填充草稿
```

如果后续获得官方授权，只需要把 Webhook 接收端或浏览器扩展 Bridge 替换成正式 Publisher 服务。

## 提交前检查

- README 已说明依赖、原创功能和能力边界。
- Demo 视频链接需要补入 README。
- 仓库截止后改为 Public。
- `npm install` 可安装依赖。
- `npm run dev` 可启动页面。
- `npm run build` 通过。
- `npm run test:run` 通过。
- PR 标题需要用一句话说明新增或修改内容。
- PR 描述需要包含功能描述、实现思路和测试方式。
- 每个 PR 只做一件事，合并后 `main` 分支保持可运行。
- 两人组队时，在 PR 备注中写清楚具体分工。
- 两名队员都需要使用自己的账号提交 commit / PR。
- 不提交账号密码、Cookie、token、`.env` 等敏感信息。
